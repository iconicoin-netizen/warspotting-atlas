# WarSpotting Loss Atlas

[Open the public atlas](https://warspotting-atlas.pages.dev/) · [Data update workflow](https://github.com/iconicoin-netizen/warspotting-atlas/actions/workflows/update-data.yml)

An interactive map of documented Russian equipment losses from WarSpotting. Filter by date, equipment category, unit, and loss status. Equipment artwork faces west in the map, legend, and record list. The website supports Chinese, English, and Ukrainian, with a language selector beside the title. The choice is saved in the browser. Filters, statistics, legends, details and offline controls are localized; source model names, unit names, locations and event dates remain unchanged. Ukrainian mode prioritizes Ukrainian basemap labels where available. Repository documentation and automation are in English.

English is the default interface language for new visitors. A previously saved language selection is still respected.

## Automatic data updates

GitHub Actions runs **daily at 01:23 UTC / 09:23 China Standard Time**. Start a manual run from **Actions → Update WarSpotting data → Run workflow**. GitHub may delay scheduled runs. Public-repository schedules can be disabled after 60 days without repository activity; successful daily metadata commits normally keep this repository active. Check Actions if updates stop.

The updater reads the [official WarSpotting API](https://ukr.warspotting.net/api/docs/). It scans the complete dataset using ascending record IDs and a latest-ID boundary captured at the start. This includes backdated additions and historical corrections. Records added during a scan are picked up on a subsequent run.

- Requests are spaced by at least 1.5 seconds, below the documented limit of 10 requests per 10 seconds.
- Transient failures and rate limits are retried with backoff and Retry-After handling.
- Empty, malformed, duplicate, non-advancing, or incomplete results fail the run. A record count drop greater than 5% requires investigation.
- Published files are written only after the entire scan passes validation. Failed runs leave the committed snapshot unchanged.
- Successful runs commit `dist/data.json` and `dist/data-meta.json`, including the UTC refresh time, record count, latest event date, and SHA-256 checksum.
- The workflow uses the repository-scoped, short-lived `GITHUB_TOKEN` with `contents: write`. No personal access token is needed. Update runs are serialized. If a concurrent human commit prevents the push, the run fails safely and can be rerun.

The website displays validated cached or bundled data first, then refreshes the next-visit cache from the latest committed GitHub data in the background through fixed Cloudflare endpoints (`/live-data.json` and `/live-overlays/*`). This avoids requiring visitors to connect directly to raw.githubusercontent.com. Edge responses may be cached for up to five minutes. The narrowly routed `dist/_worker.js` forwards only these public datasets; all other files remain static. Localhost reads the public GitHub URLs directly. A slow or unavailable GitHub response no longer blocks the first render. The source section identifies which snapshot was loaded. After the background refresh completes, reopen or refresh to load new data; an active view is not replaced mid-filter. This connection does **not** automatically deploy HTML, CSS, or JavaScript changes.

Run locally with Node.js 22 or later from the repository root; no npm dependencies are required:

```sh
node --test scripts/update-data.test.mjs
node scripts/update-data.mjs
```

The initial bundled dataset was provided as a September 22, 2026 snapshot. The metadata file generated by the workflow describes subsequent API refreshes.

## Context overlays

The only context overlay is the **UAControlMap contact line**, enabled by default. It comes from the original `Frontline` folder in [owlmaps/UAControlMapBackups](https://github.com/owlmaps/UAControlMapBackups). Original names, coordinates, widths and colors are retained; it remains separate from WarSpotting loss records. Important Areas, units and OSM fortifications are not imported, served or cached.

Source commit, source timestamp and KMZ SHA-256 accompany the dataset. Downloads are pinned to the reported commit. The control shows the source date; hovering over the count shows source and sync timestamps.

The UAControlMap backup repository does not state a reusable data licence. Its derived layers are therefore kept separate, visibly attributed, and should be reviewed before redistribution beyond this project. They are context claims from that source, not independently verified positions.

The context workflow runs daily at **02:17 UTC / 10:17 China Standard Time**. Run and test it locally with Python 3.12 or later; it has no third-party dependencies:

```sh
python scripts/update-overlays.test.py
python scripts/update-overlays.py
```

## Data provenance and scraper reference

Original records are provided by [WarSpotting](https://ukr.warspotting.net/). Each record links to its source page. Official event dates and unit names are kept as supplied by WarSpotting.

Related scraper: [lazar-bit/automated-warspotting-scraper](https://github.com/lazar-bit/automated-warspotting-scraper) by Zsolt Lazar, MIT licensed. It is a useful reference for collecting WarSpotting API data and scheduling updates. This repository implements its own ID-paginated updater; it does not claim that the initial uploaded snapshot came from that project, and does not copy or execute its code. The official API documentation is the source of truth.

## Features

- Combined multi-select filters: OR within a field, AND across fields.
- West-facing icons with distinct equipment-category colors, or optional unit/status coloring. Map markers, list icons, and legend icons share the same category colors.
- Zoom-sensitive symbol size and viewport-based opacity. Near-coincident icons in the active legend group (equipment, unit, or status) use a gradual overlap curve: dense groups become darker progressively instead of saturating after a few records. All three modes share the same diffusion and opacity rules. Counts are recomputed after changing the legend mode, panning, zooming, resizing, and filtering.
- Basemap and offline-cache setup do not block record rendering. A validated local snapshot renders before the background online request, which has an eight-second timeout; diffusion failures do not interrupt markers, lists, or statistics.
- At metric scales of 30 km and above, near-coincident symbols across equipment categories preserve the original single-symbol opacity as the composite baseline. Only the additional overlap concentration is weighted down: `0.9 * (30 km / scale)^0.15`, with a 0.5 floor. The target composite opacity is converted back into per-symbol alpha, so extra records still deepen the color without reducing the group below its single-symbol baseline. Isolated symbols, views at 20 km and below, and geographic diffusion retain their existing behavior.
- Geographic color diffusion follows the displayed metric scale: no diffusion at 10 km and below, light diffusion with a 3 km support radius at 20 km, and medium diffusion with a fixed 6 km support radius at 30 km and above. Gaussian density fields mix colors in optical absorption space before compositing, with no luminous ring. The radius uses each record's latitude and the map projection; zooming out reduces its screen size. Density opacity is capped at 38%, beneath the original equipment symbols. These distances are visual styling parameters, not equipment ranges or location uncertainty.
- Record details, monthly distribution, and fullscreen controls.
- Records without coordinates remain in the searchable list and summary counts.

## Maps and offline use

The bundled Protomaps/OpenStreetMap snapshot, dated September 21, 2026, covers Ukraine including Crimea at zoom levels 0–11. It includes major roads, cities, place names, water, and reference features. Land-use and building layers were removed to reduce size; retained layer contents were not rewritten. OpenFreeMap supplies finer online details. English labels are preferred.

Use the website's offline-map control to save the complete map in the current browser. Merely viewing an area does not save the whole map. Cache cleanup, private browsing, or storage limits can affect persistence. Detailed maps outside Ukraine require a connection.

Chunk sizes and SHA-256 checksums are recorded in `dist/map/manifest.json`. The browser verifies map chunks before use. Map data comes from Protomaps; the standard OpenStreetMap tile service is not scraped.

## Run and deploy

```sh
python -m http.server 8793 --directory dist
```

Open `http://localhost:8793`. Opening `index.html` directly is unsupported because browsers restrict adjacent JSON and map-file access.

The public site uses Cloudflare Pages Direct Upload. Upload the contents of `dist` when changing application code. For a separate Git-integrated Pages project, use no framework, no build command, and `dist` as the output directory. Automatic WarSpotting and overlay **data** updates work with the existing site without a Cloudflare API token.

## Loading and cache behavior

The contact-line switch is a compact row in the left sidebar. It moves into the map in fullscreen mode. Removed overlays are no longer downloaded or precached. The detailed MapLibre renderer (about 1 MB including CSS and integration) loads only when online detail is needed, at zoom 14 or outside the regional map. The versioned application shell uses cache-first reads; map chunks retain their existing cache keys and SHA-256 verification so previously saved offline maps remain reusable. Reads spanning chunks run in parallel and duplicate in-flight requests are shared. Bundled records are retained in the data cache without a second service-worker installation download.

Contact-line strokes use the existing 5 km view (zoom 11 at 48.5 N) as the width reference: 2.163 px and 2.744 px. Wider views reduce screen width using the ground-resolution ratio raised to 0.35, softening the reduction to improve 20–30 km legibility; closer views retain the reference pixel widths. Panning accounts for latitude. SVG zoom transforms scale the strokes during animation. Coordinates are unchanged.

In fullscreen, all map UI and the pointer hide after 3 seconds without interaction. Pointer movement, clicking, scrolling, keyboard input, or focus restores the controls immediately. Exiting fullscreen clears the idle state.
